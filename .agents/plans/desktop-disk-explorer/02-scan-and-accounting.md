# Scan engine and accounting
New crate space-core defines conceptual ScanId, RootIdentity, EntryMetadata, CoverageState, Metric and ScanPolicy. New crate space-scan defines conceptual ScanController and PlatformMetadata adapters. These symbols are proposed, not preexisting. Add platform modules for Windows, macOS and Linux; keep policy common.

## Scope and traversal
Scan one selected root per job; allow multiple saved roots. Enumerate mounted local/removable volumes for selection with OS capacity/free readings and timestamps. Do not scan all volumes automatically. Network locations are not advertised in v1; detect/warn rather than accidentally recursively traversing them. Exclude virtual filesystems, nested mount boundaries and the app's own cache directory by default. User exclusions are explicit scan policy, distinct from display filters. Record skipped boundaries and exclusions.

Use bounded blocking metadata workers, bounded queue/batches and a single store writer. Start with a tunable small fixed worker limit; benchmark SSD/HDD rather than maximizing threads. No per-file task spawning, no unbounded list of paths, no full tree in GPUI entities. Backpressure reaches enumeration. Every event carries ScanId/generation; ignore obsolete results. Cancel is cooperative between filesystem calls. Queue a replacement scan only after predecessor writer ownership is released; prevent old scan completion from publishing after cancel. Slow OS I/O may remain pending; provide honest stopping state and avoid blocking the UI.

Directory descent must use opened directory handles and platform no-follow/reparse-aware validation of the opened object before enumerating it. Recheck root/filesystem/exclusion boundaries against that object; path classification followed by unguarded path-based descent is insufficient. If safe descent cannot be established, mark a coverage gap. Test deterministic directory-to-symlink/junction substitution between inspection and open, asserting that the redirected target is never enumerated. Do not follow symlinks/junctions/redirecting reparse points; record link metadata without counting target contents. Classify Windows reparse tags so placeholders are not confused with directory redirects. Removable disconnect marks incomplete coverage and stops/reports the affected scope. Capture vanished, changed, permission-denied and unsupported metadata as typed outcomes. An unprivileged scan is normal. Explain permissions and allow rescanning after the user grants access; do not auto-elevate or modify OS security.

## Native paths and identities
Preserve raw native path components (Unix bytes; Windows native UTF-16 representation) with an encoding tag and display text separately. Never use lossy display paths as lookup/action keys. Parent IDs + native names avoid quadratic full-path duplication. Volume identity and optional device/file ID provide observed identity, but are not eternal across reformat/remount/reuse. Persist the selected root directory object identity separately from its volume identity, including observed identity strength and reuse limitations. Validate both before reconnect, live actions, refresh publication or automatic comparison. Same path and volume do not prove the same selected directory. If identity differs or continuity cannot be established, retain offline browsing but require explicit selection/validation as a new or rebound root; a rebound root starts a new comparison lineage. Drive letters and mount paths alone are not persistent identity. If stable identity is unavailable, mark weak identity and require explicit root selection on reconnect. Test non-UTF-8 names, case distinctions and long Windows paths.

## Metric contract
Default logical/apparent size: regular-file length, with separate allocated-size mode using platform metadata where available. Unknown allocated bytes remain nullable, never replaced by logical bytes without labeling. Directories sum included descendants; do not imply their aggregate is filesystem-wide used space. Each displayed total carries unknown/error counts and coverage.

Hardlink policy: within scan root, charge each observed physical file identity once to a canonical relative-native-path ordering (byte/code-unit ordering), retaining all paths with link badges. Determine attribution deterministically at final aggregation; previews may be provisional and labeled. Both metrics follow the same dedup policy; where identity is unavailable count per path and mark the estimate. Largest-files rows group known hardlink aliases; reveal lets user choose an alias. A selected subtree's charged totals remain consistent with the root tree, even when an alias's canonical owner is outside that subtree; explain alias entries with zero charged bytes and show their own length in details. Never deduplicate separate clones by content. Filesystem snapshots/clones/shared blocks mean reported allocated bytes still are not reclaimable bytes.

Keep volume capacity/used/free distinct from scanned totals and show an unexplained difference without attributing it to a specific cause. Do not read file contents or follow cloud placeholders into hydration. If an API cannot guarantee safe metadata access, skip/mark unavailable instead. Metadata scan is an observation interval, not an atomic backup/snapshot.

## Acceptance
Fixture harness covers nested mounts, hardlinks across sibling directories, missing IDs, symlink/junction cycles, sparse/compressed files, allocations unavailable, raw filenames, permission denial, concurrent rename/delete/growth and disk removal. Verify independent native metadata with identical policy. Normal scanning must not open content streams; test with instrumented adapter and real cloud-placeholder checks on supported providers. Provide no fake precision for partial scans. Native calls need real OS tests, not only mocked adapters.

Test root replacement on the same volume: rename the scanned directory away, create another at its path, and verify reconnect/reveal cannot silently target it, refresh cannot publish into the old lineage, and Changes refuses automatic continuity.
