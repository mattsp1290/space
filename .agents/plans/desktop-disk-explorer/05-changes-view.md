# Follow-on: Changes
Prerequisite: all first-release gates pass and immutable scan/coverage semantics are stable. This is approved follow-on scope, not a reason to delay the first useful tree/largest-files milestone.

New comparison module in space-core and indexed comparison queries in space-store; new Changes mode in space-app. Compare two finished scans from the same validated volume, selected-directory object and comparison lineage with identical scan policy and metric semantics. Show before/after timestamps and coverage. If identity or exclusions differ, refuse automatic comparison and explain what rescan is needed; do not silently compare mount paths.

Match by raw relative path initially. Renames appear as removed + added; label this limitation. Do not claim inode/file ID reuse proves continuity. Cover both net change and gross additions/removals; list fastest-growing directories and largest positive/negative changes. Reuse hierarchy, filters and details, but keep metric and baseline explicit.

Coverage is per subtree: a missing current entry is removed only if the parent scope was successfully enumerated in the current scan and old scope was known. When an entire old directory is proven absent by its nearest successfully enumerated current ancestor, propagate that proven absence through the previously observed old subtree; preserve old unknown coverage as unknown rather than inventing removed bytes. Test deletion of a fully observed nonempty directory separately from permission denial, including descendant counts and gross removed bytes. A newly visible entry under previously unreadable scope is newly observed, not proven newly created. Unknown subtrees propagate incomplete comparison totals. Hardlink canonical-owner changes must not manufacture unique-byte changes: compare identity-group charged accounting only where both scans establish identity; otherwise mark accounting changes or unknown rather than claiming physical growth. Scan intervals mean concurrent modifications can occur within each observation.

Keep two completed scans by default; user chooses baseline if available. No automatic trend forecasting, schedule or long-term retention promise. No hashes or content similarity. Test create/delete/grow/shrink, renamed file, denied subtree, changed exclusions, remounted root, hardlink alias changes, metric unknowns and same-size offsetting additions/removals. Independent fixture expected outputs must prove net and gross values and coverage labels. All work stays local.
