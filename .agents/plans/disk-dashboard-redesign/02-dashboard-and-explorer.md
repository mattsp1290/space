# Dashboard and focused explorer
## WP3 — presentation
Existing insertion points: Space::render and action wiring in crates/space-app/src/main.rs; treemap::view/layout in crates/space-app/src/treemap.rs; existing filters.rs, text_input.rs, changes_panel.rs, cache_management.rs. Proposed new modules under crates/space-app/src/: dashboard.rs and explorer.rs, with explicit presentation data and event enums. Keep render code separate from background orchestration.
Home: top bar Space, secondary Scan folder, primary Scan all disks (Rescan all disks when appropriate). Under it compact included-local-target count and discovery-warning link. Responsive grid: one wide card for one disk, at most two columns when room permits; narrow window uses one column. Cards show name/location, free-space bar with human-readable units, independent treemap, three largest included items, last scan time and Explore/Rescan. Stable ordering and stable bounded colors avoid unnecessary movement. Never show aggregate computer capacity or shared-volume total without verified non-overlap.
Empty first run: Finding disks then actual targets with Scan to see what is taking space. Zero supported targets gets explanation and Scan folder. Offline cached targets grouped after connected ones. Errors have Retry and Details, not disappearance. While scanning show target N of M and entries observed, not invented percent/ETA. Already-finished cards become browsable independently. Partial data says Some locations could not be read. Keep technical observation intervals and raw error details behind details disclosure.
Focused explorer: persistent disk sidebar and All disks home action, breadcrumbs/Up, large treemap filling remaining workspace, optional synchronized list and selection inspector. At ordinary 1280x800 use approximately 220px sidebar and a collapsible 280px inspector; collapse secondary panels at narrow widths rather than requiring horizontal scrolling. Replace fixed 240px map presentation with available-area responsive sizing. Scroll result panels independently, not the entire toolbar+screen. Preserve bounded treemap geometry and unknown/Other accounting.
Single click selects, double click/Enter on directory explores. Clicking a file never launches its contents. Visible Open folder action and breadcrumbs preserve discoverability. Up restores the exited folder selection; switching disks preserves per-disk last explored location when still valid, otherwise falls back to root. Stable selection is tied to scan+node, never node alone. Other opens the same scoped list through an explicit affordance. Unknown sizes are a separate count/link, never proportional zero tiles.
Largest files and Folders are labeled views with explicit Entire disk / Current folder scope. Search/filters remain discoverable, advanced fields collapsed. Show active metric in plain language; never silently switch size semantics between disks. Cache management in secondary menu, Changes accessible within the disk, aliases in item details. Preserve validated Copy path/Reveal actions and offline warnings.
Lightweight design system: consistent spacing, typography, rounded panels, high-contrast text, restrained categorical map colors, clear selected/focused states, human-readable sizes. No new asset/font dependency. Color cannot be sole status signal. Capacity/free-space bar remains separate from observed-file map. No misleading reclaimable-space claim.
Keyboard: focus order through primary action, disks, content; list provides equivalent accessible navigation without Tab traversing 128 tiles. Focus remains stable across progress updates. Important status changes announced without every entry tick. Hover is supplemental only.
Acceptance: dashboard event invokes coordinator without requiring choose-target then separate Scan; each completed card owns a clickable treemap; Explore shows its exact scan; supported views/settings remain reachable; map expands with window; narrow layout still exposes scan action and disk access. Test presentation models and event reducers and add GPUI render/layout testing where available with pinned APIs; actual native compilation is mandatory, not substituted by mocks.
