# Batch scans and per-disk data
## WP1 — model and coordinator
Existing insertion points: crates/space-app/src/main.rs Space, Running, refresh and scan completion; crates/space-app/src/backend.rs ScanRequest/scan; crates/space-scan/src/volumes.rs MountedVolume/VolumeListing. Proposed new modules under crates/space-app/src/: disk_model.rs and scan_batch.rs. Names are proposals, not existing APIs.
Create a GPUI-independent state machine for disk cards and serial batches. A card identity is the verified volume plus directory identity, never display label or lossy path. Preserve raw NativePath aliases and use exact identity validation. Saved folder roots remain distinct entries, not falsely labeled disks. Disconnected saved roots stay browsable.
Discover metadata off the UI thread on startup and batch start. Cache loading is also background work. Discovery is not source traversal. Freeze eligible targets when the batch starts; targets newly attached later are available for a later batch. Do not offer unsupported network inclusion. Expose discovery omissions through a concise Details badge, distinct from per-scan partial coverage.
Proposed ScanRequest addition: expected selected RootIdentity. Validate it against inspect_root before beginning publication, including never-scanned queued disks. Existing refresh_root alone does not protect first scans against replacement. Retain scanner's later expected-root validation. Exact alias dedup requires matching volume and directory, not volume alone; nested/bind subtrees are not interchangeable.
Use the existing single-writer scan backend serially. States: idle/discovering, queued, scanning, stopping, ready/partial, failed, cancelled, offline. Model batch generation, target key, active request generation and per-card query generation. Every callback checks all applicable identities. Advance only after the active worker returns. Stop invalidates queued starts, requests cancellation off UI, and waits for acknowledgement. Failures mark the card then advance. Shutdown cancels the active worker and does not launch another.
A target-level rescan uses the same coordinator. A folder scan is a single-target job; while scanning, disable conflicting acquisition actions with an explanation rather than introducing a second writer. Discovery refresh may update presentation but cannot replace the frozen batch identity.

## WP2 — snapshots and preview lifetime
Represent per-card published scan identity, dated summary, bounded treemap model and status separately from explorer selection. A new publication updates its card only. Retain existing explorer snapshot until user chooses updated data, avoiding geometry jumping beneath the pointer.
Open saved roots through backend::open_root on a background worker. Match mounted volumes to RootRecord using identity; do not conflate historical roots with unrelated same-path volumes. A card without a snapshot has a real empty state, never fake colored tiles. A failed/cancelled refresh keeps its last published map dated. A failed first scan has no completed map.
Preview data comes from bounded cached queries/ChildrenSummary, not source re-enumeration or only a visible list page. Keep at most 128 tiles per loaded preview, virtualize/paginate visible cards, coalesce query requests and release offscreen heavy sessions. Do not launch an unbounded concurrent job per disk. Use a small bounded background query queue and per-card generation rejection. Capacity is OS metadata and never inferred from observed file sizes.
Maintain pins only while sessions need them, including visible cards/explorer/Changes. On cache removal or clear, invalidate affected card snapshots/previews and stale callbacks; use existing pin protections and deliberate release/retirement. Retire SQLite-backed owners through existing deferred::Deferred. Never perform final SQLite destruction or blocking mutex/cancel work on UI.
Tests: three-target serial order; error then success; stop before start/during traversal/during commit/after completion; replacement before first scan; stale generation callbacks; alias and nested-root behavior; two independent preview maps; stale cards after cache deletion; offline cached reopening; active explorer not hijacked by another disk finishing. Use a fake scan executor for deterministic controller tests plus actual backend temp-cache integration for publication/identity behavior.
